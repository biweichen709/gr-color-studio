# GR III v2.10 工厂菜单与色彩调查记录

本页记录对 **GR III（普通版）固件 2.10** 的离线分析和一次实机操作结果。结论来自固件静态分析和用户在自有相机上的操作，未刷固件、未写入相机系统文件（只做只读备份）。

## 结论速览

| 问题 | 结果 |
| --- | --- |
| 能否进工厂菜单 | **能。** 机型编号 `78350`（0x1320E）+ 批量候选法实测进入成功 |
| 入口文件名 | 运行时由 `C:\%08ld.%03ld` 生成，8 位为机型编号，3 位后缀未确定 |
| 色彩风格是否为可替换的表文件 | **否。** 文件名、文件内容、固件代码三处均未发现 3D 色彩表 |
| 机内替换色彩的可行性 | **不可行。** 色彩渲染参数化写死在 DSP/ISP 固件中，无独立资源文件 |

## 工厂菜单入口（实机验证）

GR III 2.10 与 GR IV / GR IIIx 一样，启动时读取 SD 卡根目录的入口文件进入工厂菜单，但入口文件名不是以明文存储，而是在运行时用格式串 `C:\%08ld.%03ld` 拼出：

- 8 位部分是产品机型编号。GR IV = `00078560`（0x132E0），GR IIIx = `00078490`（0x1329A），据此推定 **GR III = `00078350`（0x1320E）**，并经实机验证正确。
- 3 位后缀（GR IV 为 `636`、GR IIIx 为 `609`）未能从固件推出计算规则。
- `DEVELOP.MOD` 的 10 字节密钥 `07 01 2C 1F 10 03 1E 16 05 2D` 与 GR IV / GR IIIx 相同（固件中存在该字节序列）。

因为后缀未知，采用的办法是用 GR Color Studio 的「批量写入 1000 个候选」把 `00078350.000`～`00078350.999` 全部写到卡上，相机开机时自动读取其中正确的那一个。关机后按住 MENU 再按电源键即进入工厂菜单，只需把 `Script` 设为 Enable。实测该流程使相机成功执行了卡上的 `script/startup.ttl`（备份脚本），证明入口生效。

工厂菜单的命令字（位于入口标记附近）包括 `OPEN_FACTORY_DEBUG_MENU`、`SCRIPT_EN_MODE EN`、`SERIAL_INPUT_EN_MODE`、`DBG_LOG_STORE_EN_MODE`、`THERMAL_SHUTDOWN` 等，与 GR IV 家族一致。

## 色彩表调查（三处均为否）

1. **固件引用的资源路径**：解包 2.10 固件（载荷约 59.7 MB）后提取到约 200 个相机文件路径，均为字体（`A:\Resource\Font\*.bin`）、出厂/传感器校准（`E:\` 下的 `BlkCtl*`、`MfgPrc*`、`Sr_*`、`DarkCurr`、`Awb_Gain` 等）、坏点/暗场（`DF_*`、`*PxDf*`）。无命中色彩/影像控制/LUT 的文件。
2. **固件代码内嵌**：对解包载荷做 3D 表扫描，内嵌色彩表数为 0。
3. **实机备份文件内容**：对实机备份出的全部 `.bin` 逐个做 3D 表扫描，候选色彩表数为 0。

综合判断：GR III 的影像风格（标准、鲜艳、正片等）以色调曲线、色彩矩阵、一维表等参数形式编译在 DSP/ISP 固件中，没有可被 SD 卡脚本替换的独立 3D LUT 资源文件。因此 GR IV 上可行的"文件级替换色彩表"方案不适用于 GR III。

**保留项**：该次实机备份未完整跑完，漏掉少量文件（`USERDATA.BIN`、部分 `E:\` 测试项）；色彩参数理论上也可能藏于某个未被 3D 表扫描识别的参数文件中。但这些文件属校准/测试数据或格式未知，盲目改写有损坏相机风险，未作进一步尝试。

## 安全边界

- 只读备份不改相机。任何写入只允许目标在 `A:` 资源盘，且必须先有通过校验的备份、等长、读回核对。
- **严禁**向 `E:\`、`B:\` 写入——这些是本机出厂/传感器校准数据，覆盖可能永久损坏相机。
- 操作结束后把工厂菜单 `Script` 设回 Disable，并移除 SD 卡上的入口文件与候选文件。

## 现实可用方案

GR III 想要哈苏/富士等色彩风格，用 GR Color Studio 在电脑端处理 JPG 或 DNG 即可（套预设或 .cube、微调、批量导出并保留 EXIF），不触碰相机、无风险。机内替换色彩不在 GR III 的能力范围内。

固件容器格式参考 [yeahnope/gr_unpack](https://github.com/yeahnope/gr_unpack)；工厂菜单与脚本机制参考 [radium-wang/ricoh-gr4-firmware-analysis-and-feature-expansion](https://github.com/radium-wang/ricoh-gr4-firmware-analysis-and-feature-expansion) 的 GR IV 实机研究。
